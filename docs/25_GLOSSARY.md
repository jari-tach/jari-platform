## المصطلحات

| المصطلح | التعريف |
|---------|---------|
| **API** | Application Programming Interface — واجهة برمجة التطبيقات التي تتيح للمكونات التواصل مع بعضها. |
| **DTO** | Data Transfer Object — كائن يحمل البيانات بين الطبقات أو عبر الشبكة. |
| **Entity** | كائن أعمال أساسي مستقل عن أي إطار أو نظام خارجي. يحتوي على المنطق التجاري الأساسي. |
| **Repository** | واجهة أو صنف يجرّب الوصول إلى البيانات، يخفي تفاصيل مصادر البيانات عن طبقة المجال. |
| **Use Case** | فئة ذات مسؤولية واحدة تغلف عملية تجارية واحدة. |
| **Feature** | وحدة مستقلة ذات مكوّناتها الخاصة (data، domain، presentation) تتبع نمط Feature-First. |
| **Aggregate** | مجموعة من الكيانات والقيم ذات الحدود المشتركة التي تُدار معًا كوحدة واحدة. |
| **Domain** | طبقة المجال — تحتوي على المنطق التجاري، الكيانات، حالات الاستخدام، وواجهات المستودعات. لا تعتمتم على أي إطار. |
| **Riverpod** | مكتبة إدارة حالة لـ Flutter توفر حلاً آمنًا وقابلًا للاختبار ومرنًا لإدارة الحالة. |
| **Provider** | في سياق Riverpod، كائن يوفّر قيمة أو حالة إلى الأدوات الأخرى. |
| **Failure** | كائن يمثل خطأ في طبقة المجال، يُستخدم بدلاً من استثناءات النظام الأساسي. |
| **Exception** | استثناء نوع Dart الأصلي يُستخدم للإشارة إلى حالة خطأ. |
| **Dependency Injection** | نمط تصميم يُزوّد الكائنات باعتمادياتها بدلاً من إنشائها أنفسها. |
| **DDD** | Domain-Driven Design — تصميم موجه بالمجال. |
| **SOLID** | مجموعة مبادئ تصميم كائنية التوجه الخمسة: Single Responsibility، Open/Closed، Liskov Substitution، Interface Segregation، Dependency Inversion. |
| **Microservices** | بنية معمارية تقسم التطبيق إلى خدمات صغيرة ومستقلة. |
| **Event** | حدث يصف شيئًا حدث في النظام، غالبًا ما يُستخدم للاتصال غير المتزامن. |
| **State** | الحالة — البيانات التي تتغير بمرور الوقت وتؤثر على سلوك التطبيق. |
| **Cubit** | نموذج إدارة حالة بسيط في Bloc library (يستخدم Riverpod بدلاً منه في هذا المشروع). |
| **Offline First** | نهج تصميم يفترض أن الاتصال بالإنترنت غير متاح دائمًا، ويُبنى التطبيق للعمل بدونه. |
| **Feature First** | نمط تنظيم الكود ينظم الملفات حسب الميزات بدلاً من حسب الطبقات. |
| **Repository Pattern** | نمط تصميم يفصل طبقة المجال عن طبقة البيانات عبر واجهة مستودع. |
| **Clean Architecture** | نمط عمارة يفصل المنطق الأعمال عن الأطر والواجهات الخارجية، مع تدفق اعتماديات إلى الداخل. |
| **Hexagonal Architecture** | نفس فكرة Clean Architecture، يربطها بواجهات (ports) ومحولات (adapters). |
| **Onion Architecture** | نفس فكرة Clean Architecture، يرتب الطبقات كطبقات ثعلب متداخلة. |
| **Interface Segregation** | مبدأ SOLID يفضل واجهات صغيرة ومحددة على واجهات كبيرة. |
| **Dependency Inversion** | مبدأ SOLID يفضل الاعتماد على التجريدات بدلاً من التنفيذات الملموصة. |
| **Caching** | تخزين مؤقت للبيانات لتسريع الوصول إليها لاحقًا. |
| **Serialization** | تحويل الكائنات إلى تنسيق قابل للتخزين أو النقل (مثل JSON). |
| **Deserialization** | العملية العكسية للتسلسل — تحويل البيانات المخزنة إلى كائنات. |
| **JWT** | JSON Web Token — توكن مصادقة قياسي يحتوي على بيانات مشفرة. |
| **Interceptor** | مكوّن يعترض طلبات أو استجابات HTTP قبل وصولها إلى الوجهة النهائية. |
| **Localization** | تكييف التطبيق للغة وثقافة مستخدم محدد. |
| **Internationalization** | إعداد التطبيق لدعم لغات وثقافات متعددة. |
| **RTL** | Right-to-Left — اتجاه النص من اليمين إلى اليسار (مثل العربية). |
| **LTR** | Left-to-Right — اتجاه النص من اليسار إلى اليمين (مثل الإنجليزية). |
| **Widget** | مكوّن واجهة مستخدم في Flutter. |
| **ViewModel** | نموذج عرض يدير حالة شاشة أو ميزة واحدة، يستخدم مع Riverpod StateNotifier. |
| **Immutable** | غير قابل للتغيير — الكائنات التي لا يمكن تعديل حالتها بعد الإنشاء. |
| **StateNotifier** | فئة في Riverpod تدير الحالة غير القابلة للتغيير عبر StateNotifierProvider. |
| **DTO Mapper** | دالة أو صنف يحوّل بين DTO و Entity. |
