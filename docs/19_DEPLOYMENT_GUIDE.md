## 1. نظرة عامة

يستخدم مشروع SAEQ **GitHub Actions** للتكامل والنشر المستمر. يأتي التلقائية الاختبارات، التحليل الثابت، البناء، والنشر عبر منصات متعددة.

---

## 2. خط معالجة CI

```
Pull Request
  ├─ Code Analysis (flutter analyze)
  ├─ Static Analysis (flutter analyze)
  ├─ Unit & Widget Tests (flutter test)
  └─ All checks must pass before merge
```

---

## 3. خط معالجة CD

```
Merge to main
  ├─ Build (flutter build)
  ├─ Integration Tests (flutter drive)
  └─ Deploy (Firebase App Dist)
```

---

## 4. بيئات العمل

| البيئة | الفرع | الغرض | النشر |
|--------|-------|-------|-------|
| التطوير | `dev` | التطوير المحلي | يدوي |
| الاختبار | `staging` | اختبار الجودة | تلقائي عند الدمج |
| الإنتاج | `main` | المستخدمين الحقيقيين | تلقائي عند الدمج |

| النكهة | البيئة | URL API | الميزات |

## 6. بوابات الجودة

| الفحص | الحد | إجراء الفشل |
|-------|------|-------------|
| التحليل الثابت | 0 أخطاء، 0 تحذيرات | حظر الدمج |
| تنسيق الكود | 100% منسق | حظر الدمج |
| تغطية الاختبارات الوحدوية | 80% الحد الأدنى | حظر الدمج |
| تغطية اختبارات الأداة | 70% الحد الأدنى | حظر الدمج |
| اختبارات التكامل | جميعها يجب أن تنجح | حظر الدمج |
| البناء | يجب أن ينجح | حظر النشر |

## 7. إصدار البرنامج

استخدام **الإصدار الدلالي** (MAJOR.MINOR.PATCH):

- **MAJOR:** تغييرات كبيرة (API، مخطط قاعدة بيانات، تغييرات واجهة غير متوافقة).
- **MINOR:** ميزات جديدة (متوافقة مع الإصدار السابق).
- **PATCH:** إصلاحات الأخطاء والتحسينات البسيطة (متوافقة مع الإصدار السابق).

رقم البناء منفصل ويزيد مع كل بناء: `1.0.0+1`، `1.0.0+2`، إلخ.

---

## 8. أفضل الممارسات

- تشغيل CI على كل طلب دمج.
- تشغيل CD على كل دمج إلى `main`.
- استخدام التخزين المؤقت لتسريع البناء.
- استخدام بناء مصفوفة لمنصات متعددة.
- استخدام الأصناف لنتائج البناء.
- استخدام الأسرار للبيانات الحساسة.
- استخدام متغيرات البيئة للتكوين.
- مراقبة صحة خط CI/CD.
- إبلاغ الفرق في حالة الفشل.
- الحفاظ على سير العمل جافة باستخدام سير عمل قابلة لإعادة الاستخدام.
